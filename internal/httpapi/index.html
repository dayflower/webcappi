Quick start

Replace http://localhost:8080 with your webcappi server URL in the examples below. Successful requests return image/png; these commands save it as capture.png.

Capture a URL

Send GET /capture with a URL that the webcappi server can reach.

curl --fail --get 'http://localhost:8080/capture' \
  --data-urlencode 'url=https://example.com/' \
  --output capture.png

Capture HTML

Send HTML directly as the body of POST /capture.

curl --fail 'http://localhost:8080/capture' \
  --header 'Content-Type: text/html; charset=utf-8' \
  --data-binary '<!doctype html><html><body><h1>Hello</h1></body></html>' \
  --output capture.png

To send the contents of an existing HTML file instead, use --data-binary @page.html.

The body must be non-empty HTML with Content-Type: text/html. The default file mode requires UTF-8; use html_mode=loopback for other encodings. JSON, form bodies and compressed bodies are not accepted. Do not include the url parameter on POST.

Authentication

Capture requests require Bearer authentication. Add the following option to each capture command, replacing YOUR_TOKEN with the token supplied by your administrator:

--header 'Authorization: Bearer YOUR_TOKEN'

Tokens belong in the Authorization header, not in query parameters or cookies. The API token is not forwarded to the captured site.

Parameters

Options are query parameters. GET requires url; POST requires no query parameters. Unknown or repeated parameters are rejected.

ParameterApplies toMeaning and default
urlGET onlyRequired absolute HTTP(S) URL without embedded credentials. Maximum 8192 bytes.
width, heightGET / POSTViewport in CSS pixels; defaults to 1280 × 720. Determines layout; captures the visible area unless full_page=true.
output_width, output_heightGET / POSTPNG dimensions in pixels. Omit both to keep the captured size. Specify one to resize the complete image using its captured aspect ratio (viewport or full page); the other dimension is rounded to the nearest integer, with halves rounded up and a minimum of 1 pixel. Specify both to resize and center crop.
full_pageGET / POSTCapture the full scrollable document with true. Omitted, empty or false captures the viewport. Other or repeated values are rejected.
profileGET / POSTProfile name; defaults to default. Ask your administrator for other configured names. Empty or unknown names are rejected.
ready_selectorGET / POSTCSS selector for an element to wait for before capture. The element may be hidden. Omit to skip this additional check; maximum 1024 bytes.
delay_msGET / POSTAdditional wait after readiness checks, in milliseconds. Integer from 0 to 300000; defaults to 0.
html_modePOST onlyfile (default) opens a temporary UTF-8 file. loopback serves the original document and uploaded Content-Type over temporary local HTTP.

Viewport and output size

The viewport determines the page layout. The output size determines the finished PNG dimensions. The image is resized proportionally to fill the output canvas and cropped at the center when aspect ratios differ. It is never stretched or padded. All dimensions must be positive integers within the server's configured limits.

Capture the full page

curl --fail --get 'http://localhost:8080/capture' \
  --data-urlencode 'url=https://example.com/' \
  --data-urlencode 'full_page=true' \
  --output full-page.png

The viewport still controls layout. Omitted output dimensions use the full page dimensions. Explicit output dimensions use the same resizing and center cropping. The full source and output must fit the configured width, height and pixel limits, even when shrinking the output; oversized documents return 502. Full-page capture does not scroll to load lazy content, expand nested scroll containers or traverse virtualized lists. Readiness still waits for fonts and viewport images.

Wait for page readiness

Wait for an element matching #ready, then wait one additional second before capture:

curl --fail --get 'http://localhost:8080/capture' \
  --data-urlencode 'url=https://example.com/' \
  --data-urlencode 'ready_selector=#ready' \
  --data-urlencode 'delay_ms=1000' \
  --output capture.png

Replace the URL and selector with a page that provides your readiness signal. A missing selector match causes the request to time out.

Capture behavior

  • The server retains only ETag and freshness metadata, never PNG images. Conditional GET requests can return 304 without capture while metadata is fresh, or after source validation. Unconditional GET requests always generate a new image. POST always generates a new image and returns Cache-Control: no-store.
  • Capture waits for the document load, configured readiness selectors, fonts, visible images and two animation frames. Broken visible images fail the capture. Use ready_selector for application-specific readiness; there is no network-idle check.
  • delay_ms shares the overall capture deadline. It does not extend that deadline or recheck readiness after the delay. A metadata-based 304 skips capture and its delay.
  • For posted HTML, use absolute resource URLs or <base href="https://example.com/"> to resolve relative paths. A base URL does not give the document that site's origin or storage access. Browser origin and CORS rules still apply.
  • In loopback mode, the body and uploaded Content-Type are preserved without encoding conversion or an added BOM. If the header omits charset, Chromium uses its normal encoding detection, including a BOM or <meta charset>. In file mode, charset must be omitted or UTF-8; other charset values return 415. The body must be valid UTF-8 and receives a UTF-8 BOM.

Errors

Errors return JSON with an error field and Cache-Control: no-store. The examples use curl --fail to report HTTP errors rather than save an error response as a PNG.
